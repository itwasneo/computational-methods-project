Algorithm design · Specified

Three heuristics, one objective

For a complete, symmetric 2D TSP: visit every city once, return to the start, and minimize total tour length.

MethodSelected baselineWork budget
Nearest-neighbourNearest unvisited city; deterministic tiesFixed start list
Genetic algorithmTournament selection, ordered crossover, swap mutation, elitismPopulation + generations
Simulated annealingSegment reversal, Metropolis acceptance, geometric coolingProposals per chain

For symmetric TSP, SA’s four-edge cost change is O(1); applying an accepted reversal can still be O(n).

Work units differ: equal GA generations and SA proposals do not imply equal computation3 / 10

HPC investigation · CPU first

Parallelism follows each algorithm

MethodInitial source of concurrency
Nearest-neighbourConstruct tours from a fixed set of starting cities
Genetic algorithmEvaluate individuals or construct offspring independently
Simulated annealingRun a fixed collection of independent chains

Changing worker count must not increase total searches or search budgets.

Also profile: dense distances (8n² bytes) versus on-demand computation.
MPI, GPU and deeper memory optimizations remain evidence-driven options.

Begin with correct serial code and one-node CPU measurements—not every backend at once9 / 10
