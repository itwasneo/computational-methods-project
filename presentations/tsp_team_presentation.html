1) Chosen problem

The Traveling Salesman Problem

Given a set of cities linked by roads, start from one city, visit every city exactly once, and minimize the total travel distance.

  • Each city is a node.
  • Each road distance is an edge cost.
  • A valid solution is a tour.
  • The best tour is the one with minimum total distance.

Algorithm 1

Greedy nearest-neighbour method

  • Start from the initial city.
  • Repeatedly visit the closest unvisited city.
  • Return to the starting city after all cities are visited.
Role in project: simple, fast baseline for comparison.

Strengths / limits

+Easy to implement and very fast
+Useful first approximation
−Can get trapped by early local choices
−Not guaranteed to find the optimum
Suggested time: 2 min9 / 14
Algorithm 2

Genetic algorithm

The genetic algorithm evolves a population of tours and progressively favors better tours.

  • Selection: keep or prefer shorter tours.
  • Crossover: combine parts of two parent tours.
  • Mutation: randomly swap or reverse cities to explore alternatives.
Suggested time: 2 min10 / 14
Algorithm 3

Simulated annealing

Simulated annealing improves one solution iteratively while occasionally accepting worse moves to avoid local minima.

  • Start with an initial tour.
  • Make a local change, such as swapping or reversing a segment.
  • Accept better moves; sometimes accept worse moves depending on temperature.
  • Gradually reduce temperature until the search stabilizes.
Suggested time: 2 min11 / 14
Testing plan

How we will evaluate the algorithms

Different numbers of cities

Small instances for exact comparison; larger instances for scalability.

Different configurations

Random cities, clustered cities, and road-like layouts.

Performance metrics

Total route distance, execution time, memory use when relevant.

Solution quality metrics

Distance gap from best known or exact optimum, stability across repeated runs.
